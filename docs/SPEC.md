# PortPilot — design spec

Architecture and contracts for contributors. PortPilot is a native macOS menu bar app (Swift 5 language mode,
SwiftUI + AppKit, macOS 14+, not sandboxed). The project is generated by XcodeGen (`project.yml`) and built with
`xcodebuild`. It is a single app module, so everything uses `internal` (default) access; nothing is `public`.

## Purpose

Developers who build many tools end up with dev servers on random ports (53000, 52000, 32000…). They use RAM and
CPU, slow the Mac down, and it is often unclear whether a tool really closed or is still running. Some are started by
launchd, pm2 or Docker and come back after they are killed or after a restart.

PortPilot lives in the menu bar next to Wi-Fi and starts at login. Every few seconds it checks which TCP ports are
listening, shows which project folder each one comes from with its CPU and memory, and stops the ones the user made
with one click, including servers that would restart on their own (Stop & Disable Auto-Start). It never stops the
user's terminal, editor, coding agent or anything else the server was merely started from.

User-facing text is English, short and plain, in the style of macOS system UI.

Layering: Core is pure model and system queries (no UI, no process control). Control talks to launchd, pm2, Docker
and sends signals. App wires them together; UI only reads `AppStore` and calls its actions.

Threading:
- `AppStore` is `@MainActor`; it never runs a syscall-heavy scan, a subprocess or a signal on the main thread.
- `ScanEngine` runs scans on its serial utility `queue`. Work behind a button (fresh kill plans for Stop, Startup Items,
  plan previews, "still running" leftovers) runs on its concurrent user-initiated `controlQueue`, so it never waits
  behind a slow scan; what both queues read (`recentScans`: the latest scans' process tables and sockets) is guarded by
  `stateLock`. Control actions run through `ScanEngine.perform` or `OffMain.run` on a global user-initiated queue.
- `Shell.run`'s pipe readers run at the caller's QoS (user-initiated for actions, utility for scans), so an action never
  waits on lower-priority work.
- `ProjectResolver` probes the file system on its own serial queues, one per privacy-protected folder (below).

### Data flow per tick

Default interval 3 s (1 s minimum, with 25 % timer tolerance so macOS can coalesce wakeups). Scans keep running while
the panel is closed so the menu bar count, new-port notifications and "still running" detection stay live, but a
closed-panel tick stops right after the socket walk when no listener changed since the last full scan
(`ListenerFingerprint`: identity, name, parent and sockets of every listener) and that scan was final (no project
lookup pending, no folder awaiting access, no action since). Opening the panel publishes the newest scan at once and
triggers an immediate full rescan.

1. `ProcessScanner.scan(includeOtherUsers:)` → `RawScan`: the process table from one `sysctl(KERN_PROC_ALL)` and the
   listening TCP sockets of every same-user process through libproc. When system processes are shown, other users'
   listeners come from the kernel PCB list (`net.inet.tcp.pcblist_n`), or from one `netstat -anv -p tcp` run when
   that list is unavailable.
2. CPU and memory for every listener and its descendants (`ProcessScanner.usage(for:)`, CPU % from the delta since the
   previous sample of the same process).
3. `ManagerMaps` (launchd labels, pm2 apps, Docker containers), each gathered only when a listener needs it (budget below).
4. `ListenerBuilder.build(...)` → `[ListenerGroup]`, using `ProjectResolver`, `Classifier` and `ProcessTraitsCache`.
5. A `KillPlan` (`KillPlanner.plan`, or `ScanEngine.clusterAppPlan` for pm2 cluster rows) for the listeners of the
   expanded rows only, so the UI can preview exactly what Stop will end (`ScanRequest.planGroupIDs`; a row expanded
   between scans gets its plans from `ScanEngine.plans(for:)`). Headless modes plan every listener. Stop always
   computes fresh plans.
6. `ScanOutput` is applied on the main actor into `AppStore.latest`: plans, the menu bar count (assigned only when it
   changes), new-port notifications and the folder-access notice. While the panel is open it is published at once
   (`snapshot`, visible groups, respawn detection); while it is closed it waits in `latest`, so nothing only the panel
   shows changes in the background. Groups whose ports all closed on their own are checked for leftovers ("Still
   running · no open port"). Startup items are re-read only while the panel is open: when it opens, every 15 s and
   after every action.

### Performance budget

- A scan costs < 15 ms of CPU on a machine with ~800 processes (`EnginePerformanceTests`; the live-system benchmarks run
  with `PORTPILOT_PERF=1`). Showing system processes (other users) costs more and is off by default.
- Never one subprocess per process. Per tick, at most:
  - `launchctl list`, only when a listener or one of its ancestors was started by launchd directly, and then only
    when such a process started after the last read (`launchdLabelsNeedRefresh`; at least every 5 min as a safety
    net); job details are cached per label and pid, so an unchanged job costs no plist read or `launchctl print`;
  - `pm2 jlist`, only when a PM2 God Daemon is a listener or an ancestor of one, and only when the daemon or its
    children changed;
  - `docker ps` + `docker inspect`, only when a Docker / OrbStack / Colima backend owns a listener (cached 5 s);
  - `netstat`, only as the fallback described above.
- Startup items cost one `launchctl list` and one `launchctl print-disabled` per refresh, and refresh only while the
  panel is open.
- With the panel closed and nothing changing, a tick costs the process table and the fd walk (≈ 5 ms of CPU on a busy
  Mac) and touches no observed state, so SwiftUI re-renders nothing.
- The login-shell PATH used to find tools is captured once, off the main thread.
- Per-identity caches (process details, CPU samples, `ProcessTraits`, ancestry answers) and the resolver's 60 s
  directory cache keep a steady-state tick to dictionary lookups. All of them are pruned with the process table.
- The UI must not add idle cost: while the panel is hidden the list is replaced by an empty frame, and the header's
  "Updated …" label has a fixed width so its once-a-second change never re-lays out the rows.

**Never run a `pm2` command unless a PM2 daemon is running** for the user (`PM2Service.isDaemonRunning()`): any pm2
command, even `pm2 jlist`, starts a daemon when none is running.

## Shared model (Core/Models.swift)

Every module codes against these types. The file has no side effects (no syscalls, no shell, no UI).

- `ProcessIdentity` (pid + start time in µs): PIDs are recycled, so every action re-verifies the start time first.
- `ProcessBasic` (pid, ppid, pgid, uid, 16-char `comm`, start time) for every process; `ProcessTable` indexes them
  (`ancestors(of:)` nearest first, `descendants(of:)` breadth first, both cycle-safe; `isAlive(_:)`).
- `ProcessDetails` (executable path, argv, exec-time environment, cwd), cached per identity. `commandLine` quotes
  arguments with spaces and drops trailing empty arguments (left behind by processes that rewrite their title, such as
  nginx, redis and npm).
- `ListeningSocket` (port, address, family, pid). The address is `"127.0.0.1"`, `"::1"`, `"*"` (any) or a concrete
  address; `isLoopbackOnly` / `isExposed` drive the Network badge.
- `ResourceUsage`: CPU as percent of one core (Activity Monitor convention) and physical footprint in bytes.
- `ListenerCategory`: `.project`, `.service` ("Background Services"), `.app`, `.system`, in display order.
- `LaunchOrigin` (kind + name): what started a tree ("Claude Code", "Codex", "VS Code", "Terminal", "launchd"…).
- `ProcessManager`: `.none`, `.launchd(LaunchdJob)`, `.pm2(id:name:)`, `.docker(DockerContainer)`, `.watcher(name:)`.
  `isAutoRestarting` is true for launchd jobs with KeepAlive or RunAtLoad, pm2 and Docker; `badge` is "launchd",
  "brew services" (Homebrew labels), "pm2", "Docker" or the watcher's name.
- `ProjectInfo` (root path = grouping key, display name, `subpath` of the process's package, marker files).
- `ListenerProcess`: one process with at least one listening socket. `usage` is the process alone; `treeUsage` adds its
  descendants except those that are listeners themselves. `ports` is stored (sorted, distinct).
- `ListenerGroup`: one row. `id` is `"project:<root>"`, `"launchd:<label>"`, `"docker:<containerID>"`, `"pm2:<name>"`,
  `"app:<bundlePath>"` or `"pid:<identity>"`. `path` is always a folder (never a file such as a plist).
  `usage` = Σ `treeUsage` + `extraUsage`, where `extraUsage` is what else Stop ends (the runner that launched the
  servers and its other children), each process counted in one group only. `manager` prefers an auto-restarting
  manager over a watcher.
- `ScanSnapshot` (date, groups, table, scan duration, count of uninspectable listeners).
- `StartupItem`: a launchd agent as listed in Startup Items (label, plist, command, RunAtLoad / KeepAlive, disabled,
  loaded, pid, last exit status, ports filled in by `AppStore`).
- `StopMode` (`.graceful`: SIGTERM, wait, then SIGKILL; `.force`: SIGKILL), `KillPlan` (root, targets children first,
  summary lines, `requiresAdmin`, warnings), `StopResult`, `StopFailure`.
- `StoppedRecord`: what Recently Stopped shows and Relaunch reruns. Kept in memory only, never written to disk,
  because the environment may contain secrets. `canRelaunch` is false for launchd, pm2 and Docker items, which are
  restarted through their manager.
- `AppSettings` (Codable, stored as JSON in UserDefaults under `settings.v1`): refresh interval (3 s), show apps (off),
  show system (off), menu bar count (on), launch at login (on), notify on new ports (off), graceful timeout (3 s),
  hidden group ids and ports, sort order (port), heavy CPU threshold (80 %), heavy memory threshold (1.5 GB), check
  for updates (on). `AppSettings.decoded(from:)` merges stored keys over the defaults field by field, so a new field (or
  one stored value that no longer decodes) never resets the other settings.
- `Banner` (style, message, optional action): `.disableAutoStart(groupID:launchdLabels:)` (the labels let the action
  work after a Stop unloaded the jobs and their group left the list) and `.relaunch(recordID:moreRecordIDs:)` (Undo of a
  Stop that ended several servers).
- `Format`: bytes, CPU, uptime and `abbreviatePath` ("~/…"). `Format.displayHome` is the folder shown as "~": the real
  home, unless demo data sets a fictional one with `Format.setDisplayHome(_:)`.

## Core contracts

### Core/SysProc.swift

Thin, memory-safe wrappers over libproc and sysctl. Every function is a pure query, bounds-checks every buffer and
returns nil (never crashes) when a process is gone, not inspectable or returns something unexpected.

```swift
enum SysProc {
    /// sysctl(KERN_PROC_ALL), retried on ENOMEM. Skips pid 0 and zombies.
    static func allProcesses() -> [ProcessBasic]
    static func basic(pid: Int32) -> ProcessBasic?
    static var currentUID: UInt32 { get }
    static func executablePath(pid: Int32) -> String?                     // proc_pidpath
    static func argumentsAndEnvironment(pid: Int32) -> (arguments: [String], environment: [String: String])?
    static func parseProcArgs(_ buffer: UnsafeRawBufferPointer) -> (arguments: [String], environment: [String: String])?
    static func currentDirectory(pid: Int32) -> String?                   // PROC_PIDVNODEPATHINFO
    /// Path + argv/env + cwd; the identity is re-verified after all reads.
    static func details(for basic: ProcessBasic) -> ProcessDetails?
    /// TCP sockets in LISTEN state (PROC_PIDLISTFDS + PROC_PIDFDSOCKETINFO). nil when the process can't be inspected,
    /// [] when it has none. Deduplicated and sorted; the inout variant reuses one descriptor buffer per scan.
    static func listeningTCPSockets(pid: Int32) -> [ListeningSocket]?
    static func listeningTCPSockets(pid: Int32, fdBuffer: inout [proc_fdinfo]) -> [ListeningSocket]?
    /// Every listening TCP socket on the system from `net.inet.tcp.pcblist_n` (all users, attributed to
    /// so_last_pid). nil when the list is unavailable or its record layout is not the known one.
    static func systemTCPListeners() -> [ListeningSocket]?
    static func parsePCBList(_ buffer: UnsafeRawBufferPointer) -> [ListeningSocket]?
    /// proc_pid_rusage(RUSAGE_INFO_V4): CPU nanoseconds (mach ticks converted) and phys_footprint.
    static func resourceSample(pid: Int32) -> (cpuNanos: UInt64, footprintBytes: UInt64)?
    static func socketOrder(_ lhs: ListeningSocket, _ rhs: ListeningSocket) -> Bool
}
```

Socket addresses: an unspecified address is reported as `"*"`. A v4-mapped IPv6 address (`::ffff:a.b.c.d`) and an
AF_INET6 socket whose PCB is IPv4-only (the version flags win over the socket family) are reported as `.ipv4` with
the plain IPv4 address. PROC_PIDLISTFDS truncates silently, so a full buffer is regrown and the call retried a bounded
number of times (`maxDescriptorListAttempts`).

### Core/ProcessScanner.swift

```swift
struct RawScan {
    let table: ProcessTable
    let socketsByPID: [Int32: [ListeningSocket]]
    /// Other users' listener pids (sockets from the PCB list or netstat; no details available).
    let restrictedPIDs: Set<Int32>
}

final class ProcessScanner {
    init(systemListenerProvider: @escaping () -> [ListeningSocket]? = SysProc.systemTCPListeners,
         netstatProvider: @escaping () -> String? = ProcessScanner.runNetstat,
         currentUID: UInt32 = SysProc.currentUID)
    func scan(includeOtherUsers: Bool) -> RawScan
    /// Cached per identity (re-read when p_comm changes, i.e. after an exec); pruned on each scan.
    func details(for basic: ProcessBasic) -> ProcessDetails?
    /// CPU % since the previous sample of the same identity (0 on the first sample) + footprint.
    func usage(for basics: [ProcessBasic]) -> [Int32: ResourceUsage]
    static func parseNetstatListeners(_ output: String) -> [ListeningSocket]
}
```

Safe to call from any thread: the descriptor buffer and the caches have separate locks, so `details(for:)` and
`usage(for:)` never wait for a running scan.

### Core/ProcessTraits.swift

`ProcessTraits` holds the per-process classification facts that depend only on a process's comm, executable, argv and
exec-time environment (boundary, protected, PM2 daemon, display name, frameworks, PM2 cluster worker).
`ProcessTraitsCache` (thread-safe, owned by `ScanEngine` across ticks) computes them once per identity, and memoizes
the answers that depend on a listener's whole ancestry (watcher, launch origin, kill-plan launch root) while that
ancestry is unchanged. An entry is reused only while the process looks the same (same comm, same kind of details).

```swift
final class ProcessTraitsCache {
    func traits(for basic: ProcessBasic, details: ProcessDetails?) -> ProcessTraits
    func watcherName(for listener: ProcessIdentity, lineage: Lineage, compute: () -> String?) -> String?
    func origin(for listener: ProcessIdentity, lineage: Lineage, launchdLabel: String?,
                compute: () -> LaunchOrigin?) -> LaunchOrigin?
    func launchRoot(for listener: ProcessIdentity, lineage: Lineage, projectRoot: String?,
                    compute: () -> ProcessBasic) -> ProcessBasic
    func prune(keepingAliveIn table: ProcessTable)
}
```

### Core/ProjectResolver.swift

Maps a process to the project folder it belongs to (the grouping key). Thread-safe (`NSLock`); directory answers are
cached for 60 s; manifests are read up to 256 KB. The file system is injectable so the heuristics are tested against a
fake tree.

```swift
final class ProjectResolver {
    static let defaultProbeDeadline: TimeInterval   // 0.2 s
    init(homeDirectory: String = NSHomeDirectory(),
         fileExists: ((String) -> Bool)? = nil, readFile: ((String) -> Data?)? = nil,
         listDirectory: ((String) -> [String]?)? = nil,
         now: @escaping () -> Date = Date.init,
         probeDeadline: TimeInterval = ProjectResolver.defaultProbeDeadline)
    /// Blocks at most `probeDeadline`; may return a provisional answer (below).
    func resolve(details: ProcessDetails?) -> ProjectInfo?
    func provisionalProject(for details: ProcessDetails) -> ProjectInfo?
    /// Protected folders whose probes are blocked right now (most likely behind a folder-access prompt).
    func foldersAwaitingAccess() -> [String]
    func waitForPendingProbes(timeout: TimeInterval) -> Bool               // headless modes and tests
    var pendingProbeCount: Int { get }
    /// Synchronous walk (probes the disk on the calling thread).
    func project(forDirectory directory: String) -> ProjectInfo?
    func protectedFolder(containing path: String) -> String?
    static func workspaceLocation(forWorkspacePath path: String) -> (directory: String, fileName: String)?
    // Pure helpers used by the rules below and by tests: packageJSONDeclaresWorkspaces, packageJSONDescribesProject,
    // tomlDeclaresTable(_:named:), gradleSettingsIncludeProjects, composeFile(_:references:), packageJSONName,
    // tomlName(_:tables:), isGenericName, isGenericPartName, isProjectSubfolderName, childOnPath(from:to:),
    // strippingDependencyFolders, normalize, parent(of:), lastComponent(of:), join.
}
```

`resolve(details:)` tries, in order: the cwd (unless "/", inside an app bundle or a system folder); the script inferred
from argv (first existing absolute file argument, cut at node_modules / .venv / venv / site-packages / .bin);
`$VIRTUAL_ENV`; the executable when it lives in a project (`~/code/foo/target/debug/server`). It returns nil for
$HOME itself, for top-level containers (~/Downloads, ~/Desktop, ~/Documents, ~/Developer, ~/code…), for tool caches
and ~/Library, and outside $HOME except code folders that have markers (/opt, /srv, /var/www, /tmp, /Users/Shared,
/Volumes/<name>). iCloud Drive and File Provider folders behave like $HOME.

Walk (`project(forDirectory:)`): up from the folder, stopping below $HOME or the top-level container. The root is
the nearest ancestor with `.git` (folder or file). Without git, a package joins an enclosing folder only on real
evidence:
1. the enclosing folder declares a workspace (package.json `workspaces`, pnpm-workspace.yaml, lerna / nx / turbo /
   rush, go.work, Cargo `[workspace]`, a multi-project Gradle build, a Maven aggregator, a uv or Deno workspace, a Mix
   umbrella); the outermost one wins;
2. a manifest folder above takes the package in when one of its compose files builds or mounts it, or when the
   package folder is just a generic part ("backend", "web", "api"…), also across workspace folders such as `packages/`;
3. a generic part whose parent holds no manifest is grouped under that parent ("Harbor Notes/backend" and
   "Harbor Notes/frontend" → "Harbor Notes").

A README, a .gitignore, a Makefile or a dependency-only package.json in a folder of unrelated tools never merges them;
each distinctly named sub-folder stays its own project. `subpath` is the nearest manifest folder relative to the root.

A folder without any marker counts only for language runtimes (`python -m http.server` in a folder of HTML) and for
binaries that live in that folder, never for tools that merely inherited a cwd (an MCP server, an agent).

Apps: an executable inside a `.app` bundle belongs to a project only when the user builds it: the bundle sits inside a
project folder (`build/`, `dist/mac-arm64/`), or it is an Xcode build product whose DerivedData `info.plist` names the
project through `WorkspacePath` (default and custom `-derivedDataPath` locations). Installed apps never do.

Name rule: `name` from package.json, pyproject.toml (`[project]` or `[tool.poetry]`) or Cargo.toml (`[package]`) at the
root. When it is missing, generic ("app", "backend"…), a template default ("vite-project") or scoped ("@org/x"): a root
that only wraps one package takes that package's name; otherwise the root folder name, prefixed with its parent when
the folder name is generic ("acme-deploy/release").

Privacy prompts: the first read inside ~/Downloads, ~/Documents, ~/Desktop, iCloud Drive, a File Provider folder or
another volume can block until the user answers the macOS folder-access prompt. Probes therefore run on one serial
queue per protected folder, and `resolve` waits at most `probeDeadline`. A late probe keeps running; meanwhile the
answer is provisional (the working folder named after itself, for runtimes and binaries that live there; nil for apps
and tools that only inherited the cwd), and the real answer is used by the next scan. Repeated scans never queue
duplicate probes behind a blocked one.

### Core/Classifier.swift

Pure string heuristics (except `appBundle(forExecutable:)`, which reads and caches one Info.plist per bundle). Safe
from any thread.

```swift
enum Classifier {
    /// .system:  other uid, an executable under /System, /usr/libexec, /usr/sbin, /sbin, /usr/bin (except dev
    ///           runtimes), /Library/Apple, or an Apple daemon that could not be inspected.
    /// .project: has a ProjectInfo.
    /// .app:     an executable inside a *.app bundle that has no project (installed apps: VS Code helpers,
    ///           Spotify…), except well-known servers shipped inside an app (Postgres.app, Ollama.app) → .service.
    /// .service: everything else the user owns (Homebrew postgres/redis, tunnels, launchd agents).
    static func category(basic: ProcessBasic, details: ProcessDetails?, project: ProjectInfo?,
                         manager: ProcessManager, currentUID: UInt32) -> ListenerCategory
    static func isSystemExecutable(_ path: String) -> Bool
    /// Inside a GUI app bundle; runtimes in a framework's Python.app and Electron builds under node_modules don't count.
    static func isApplicationExecutable(_ path: String) -> Bool
    /// Outermost .app → CFBundleDisplayName / CFBundleName, or the folder name when it is a longer form of it.
    static func appBundle(forExecutable path: String) -> (name: String, bundlePath: String)?
    /// Framework badges from argv / executable (Vite, Next.js, Astro, uvicorn, FastAPI, Django, Jupyter, Gradio,
    /// PostgreSQL, Redis, Ollama, cloudflared…).
    static func frameworks(details: ProcessDetails?, comm: String) -> [String]
    /// Row label: "vite", "next dev", "uvicorn app.main:app", "python app.py", "nginx worker"…
    static func displayName(basic: ProcessBasic, details: ProcessDetails?) -> String
    /// Who started the tree: a real launchd label wins; then ancestors (coding agents such as Claude Code and Codex,
    /// terminals, IDEs, tmux, PM2); then the exec-time environment (CLAUDECODE / CLAUDE_CODE_*, CODEX_*,
    /// TERM_PROGRAM, __CFBundleIdentifier, VSCODE_*, CURSOR_*, TMUX), which survives re-parenting to launchd.
    static func origin(details: ProcessDetails?, ancestors: [ProcessBasic],
                       ancestorDetails: (Int32) -> ProcessDetails?, launchdLabel: String?) -> LaunchOrigin?
    /// Watcher / supervisor among self + ancestors (nearest first, stopping at boundary processes): nodemon,
    /// tsx watch, node --watch, bun --watch/--hot, uvicorn/gunicorn --reload, Flask/Django reloaders, watchfiles,
    /// cargo watch, air, entr, watchexec, concurrently, turbo, dotnet watch, supervisord…
    static func watcherName(for basic: ProcessBasic, details: ProcessDetails?, ancestors: [ProcessBasic],
                            ancestorDetails: (Int32) -> ProcessDetails?) -> String?
    /// This process itself restarts its child on file changes (the kill planner climbs to it). supervisord is not
    /// one: it runs many unrelated programs.
    static func isWatcherProcess(basic: ProcessBasic, details: ProcessDetails?) -> Bool
    /// node, python, bun, deno, ruby, php, java, go, dotnet, beam.smp, perl… (version suffixes ignored).
    static func isDevRuntime(name: String) -> Bool
    /// Processes that must never be killed as part of a plan: interactive shells, terminal emulators, IDEs and their
    /// helpers, coding agents (native, node/bun/python packages, CLI shims, renamed titles), multiplexers, SSH
    /// sessions (not `ssh -N` tunnels), terminal editors, the PM2 daemon, container runtimes, OS processes, launchd
    /// and PortPilot itself. Xcode's command-line toolchain (make, git, swift inside Xcode.app/Contents/Developer)
    /// is not the Xcode IDE.
    static func isBoundaryProcess(basic: ProcessBasic, details: ProcessDetails?) -> Bool
    /// Processes that only launch the real server: npm/npx/pnpm/yarn (also npm's rewritten "npm run dev" title and
    /// Corepack entry points), `bun run|x|exec` and `bun <script>`, deno task, make (also when a shim execs
    /// `gnumake`), just, turbo, nx, concurrently, nodemon, foreman, overmind, honcho, `poetry|uv|pipenv run`,
    /// `cargo run|watch`, `go run`, bundle exec, `dotnet run|watch`…
    static func isRunnerProcess(basic: ProcessBasic, details: ProcessDetails?) -> Bool
    static func isPackageManagerScript(_ script: String) -> Bool
    static let packageManagerNames: Set<String>   // npm, npx, pnpm, pnpx, yarn, yarnpkg, corepack
    /// `sh/bash/zsh -c …` or a shell running a script file, not attached to a terminal.
    static func isScriptShell(basic: ProcessBasic, details: ProcessDetails?) -> Bool
}
```

### Core/ListenerBuilder.swift

Pure with respect to the system: it only uses the values and closures passed in.

```swift
struct ManagerMaps {
    var launchdLabelsByPID: [Int32: String] = [:]   // from LaunchdService.runningJobLabels()
    var launchdJobs: [String: LaunchdJob] = [:]
    var pm2ByPID: [Int32: (id: Int, name: String)] = [:]
    var dockerByPort: [UInt16: DockerContainer] = [:]
}

enum ListenerBuilder {
    static func build(raw: RawScan, details: (ProcessBasic) -> ProcessDetails?, usage: [Int32: ResourceUsage],
                      resolver: ProjectResolver, maps: ManagerMaps, currentUID: UInt32,
                      traits: ProcessTraitsCache? = nil,
                      sampleUsage: (([ProcessBasic]) -> [Int32: ResourceUsage])? = nil) -> [ListenerGroup]
    /// Display name for a launchd label, shared by the project list and Startup Items.
    static func launchdTitle(for label: String) -> String
    static func launchdTitle(for label: String, keepingVendor: Bool) -> String
    /// Folder of a service without a project: its cwd, else the folder of the script (interpreters, shells) or
    /// program it runs. Never a file, "/", a system folder or a spot inside an app bundle.
    static func serviceFolder(for details: ProcessDetails?) -> String?
    static func frameworks(forImage image: String) -> [String]
    static func precedes(_ lhs: ListenerProcess, _ rhs: ListenerProcess) -> Bool   // first port, then pid
}
```

- `traits` is the per-process memo kept across ticks by `ScanEngine` (a throwaway one when nil). `sampleUsage` samples
  processes that are not in `usage` (launch roots and their other children); when nil only `usage` is used.
- Projects are only resolved for same-user processes that are not boundary processes: an agent or terminal that opened
  a port inside a project folder never joins that project's group.
- Manager resolution walks self + ancestors, stopping at boundary processes: the first pid with a launchd label that is
  neither `application.*` (a GUI app instance) nor `com.apple.*` → `.launchd` (unknown job details assume RunAtLoad);
  a pm2 pid → `.pm2`; else a watcher → `.watcher(name)`; else `.none`.
- Docker: the sockets of a backend process (a non-runtime, project-less process) on ports in `dockerByPort` become one
  `.docker` listener per container, with no host usage (the container runs in the VM).
- PM2 cluster mode: the God Daemon is the Node cluster primary and holds the apps' sockets. They go to the cluster-mode
  apps among its children that `pm2 jlist` knows, by the app's PORT setting, else to the only app left without one;
  each becomes a `.pm2` listener whose usage is its workers' trees. These rows are stopped through pm2 and never
  signalled; sockets that match no app stay with the daemon.
- Grouping: project root (`project:<root>`), else launchd label (`launchd:<label>`), else Docker container
  (`docker:<id>`), else pm2 app (`pm2:<name>`), else app bundle (`app:<bundlePath>`), else the listener's launch root
  (`pid:<identity>`), which is `KillPlanner`'s plan root, so servers started by one `npm run dev` share a row.
- Titles: the project name; `launchdTitle` for launchd groups; the container, pm2 app or app name; else the process
  label. Subtitles: a project's package folders ("frontend, backend") or its process label; at most two distinct
  process labels for launchd, pm2 and app groups; the image for a container; the folder or command of a lone
  process.
- `launchdTitle`: Homebrew labels show their formula ("homebrew.mxcl.postgresql@16" → "postgresql@16"). Reverse-DNS
  labels lose their top-level domain; the vendor segment is dropped only when one specific name remains
  ("com.acme.docs-frontend" → "docs-frontend") and kept, joined with spaces, when the rest is a generic word or
  several segments ("com.northwind.app" → "northwind app", "com.example.status.tunnel" → "example status tunnel").
  Two jobs with the same short title keep their vendors. Other labels are returned unchanged.
- Usage: `treeUsage` is the listener's own tree (descendants that are listeners report their own subtree, so nginx and
  uvicorn workers are never counted twice). `extraUsage` adds each launch root that is not a listener and its other
  children, pruned like `KillPlanner` prunes targets, each process counted in the first group that reaches it.
- Groups come back sorted by first port (`AppStore` re-sorts per settings); processes inside a group by first port.

  returns its task): listeners of a user launchd job are booted out (until next login) and then checked for 1.5 s: a
  listener the job had detached (setsid, a daemonizing fork) is stopped through its kill plan. pm2 apps are stopped
  through pm2 (`pm2 stop`, a cluster app as a whole; never signalled) and Docker containers through Docker. Everything
  else is stopped by its fresh kill plan through `ProcessKiller`, with the relaunch command read before the stop. A
  listener that exited since the scan is looked up again (same group, or same folder and command, e.g. a watcher's
  restart) before Stop reports "had already exited"; a different program now on the port is named and never stopped.
- Apps and macOS services: a plain Stop of an app group asks each GUI app among the plan roots to quit
  (`NSRunningApplication.terminate()`, like ⌘Q; it can ask to save) and waits the graceful timeout; it never force-quits,
  and its helpers are signalled only after it quit. Other app and system targets get SIGTERM only
  (`escalate: false`); only Force Kill sends SIGKILL. Apps and system services get no Recently Stopped record or Undo.
- Stop & Disable Auto-Start: launchd jobs through `stopAndDisableIfReversible` (a job Startup Items couldn't switch
  back on is only stopped, with a note to turn it off in System Settings › General › Login Items); pm2 through
  `pm2 delete` plus removing the app from pm2's saved list (the banner adds `PM2SavedListUpdate.note`); Docker through
  `docker update --restart=no` + `docker stop`.
- Banners (`StopReport`) report each outcome. A plain Stop of a reversible auto-start job offers Disable Auto-Start
  carrying the unloaded labels; a stop with relaunchable records offers Undo for all of them. A stopped port that comes
  back within 20 s raises a "came back" banner naming who restarted it, with Stop & Disable when an auto-restarting
  manager did. A tool that closed its ports on its own gets a short "my-app closed (:5173)" note while the panel is
  open; it never replaces other feedback, only an older note.
- Stop All Projects (`stopAllProjects()`) stops `stoppableProjects` concurrently and reports them in one summary
  banner, with one Disable Auto-Start or Undo covering all of them.
- Relaunch / Undo (`relaunch(_:)`, `.relaunch` banner action): every record of that stop is relaunched together
  (`Relauncher.relaunchAndVerify`). Success is reported only once the process stayed up and, when it had ports, one of
  them listens again (up to 15 s); a record whose process exited stays in Recently Stopped.
- Startup items: `setStartupItem(_:enabled:)`; `startStartupItem(_:)` kickstarts a loaded job, or loads an unloaded one
  (and kickstarts it when it doesn't run at load), then reports launchd's view a second later. PortPilot's own login
  agent is never listed.
- "Still running · no open port": groups (projects and services without a manager or with a watcher, the user's own)
  whose ports all closed without PortPilot stopping them (not busy, not in the respawn watch, not hidden) are checked
  for leftovers; `stopStillRunning(_:mode:)` stops what is left, re-verified by `ProcessKiller`.
- Settings persist on change (`settings.v1`, decoded with `AppSettings.decoded(from:)`). Launch at login is managed
  only from an installed copy (/Applications or ~/Applications): the agent is repaired before the switch is computed,
  other copies show the truth (on only if the agent already points at them) and a change there snaps back with a
  warning. Those copies never store their switch (`settingsDataToStore`): the stored choice, or the default (on)
  while none is stored, is what Move to Applications and the installed copy's first run follow. The agent is written
  off the main thread; quitting with the switch off boots out PortPilot's own job.
- Convenience actions open localhost URLs, reveal folders in Finder, open a terminal (iTerm2, Ghostty, Warp or
  Terminal) in the folder (a file's parent folder), open the first installed editor (Cursor, VS Code, Antigravity, Zed,
  Xcode), and copy text.

### Control/KillPlanner.swift

Decides what Stop signals. Pure: it only reads the process table and the `details` provider, so it runs for every
listener on every scan and is unit tested.

```swift
enum KillPlanner {
    static func plan(for listener: ListenerProcess, table: ProcessTable,
                     details: (ProcessBasic) -> ProcessDetails?, currentUID: UInt32,
                     ownPID: Int32 = getpid(),
                     socketsByPID: [Int32: [ListeningSocket]] = [:]) -> KillPlan
    /// Only the listener ("Stop Only This Process" in a process row's menu).
    static func singleProcessPlan(for listener: ListenerProcess) -> KillPlan
    /// Classifier.isBoundaryProcess or the planner's own rules (session plumbing, agents and editors, interactive
    /// shells and REPLs, the PM2 daemon, ipykernel, anything inside an app bundle except dev runtimes).
    static func isProtected(_ basic: ProcessBasic, details: ProcessDetails?) -> Bool
    /// The PM2 God Daemon or a Docker backend: never signalled, not even as the listener.
    static func isManagerDaemon(_ basic: ProcessBasic, details: ProcessDetails?) -> Bool
    static func managerDaemonWarning(_ basic: ProcessBasic, details: ProcessDetails?) -> String?
    static func isPackageManagerProcess(_ basic: ProcessBasic, details: ProcessDetails?) -> Bool
    /// The program file an interpreter runs (`node -r dotenv/config server.js` → "server.js").
    static func scriptOperand(_ arguments: [String]) -> String?
    static func label(for basic: ProcessBasic, details: ProcessDetails?) -> String   // "npm run dev", "node vite"
}
```

1. Nothing to signal: pid ≤ 1 or PortPilot itself (protected plan), a Docker listener (stopped through Docker), a
   manager daemon (warning only), or a listener whose pid no longer matches the table (single-process plan).
2. Launch root: climb the ancestors while they are same-user, pid > 1, not PortPilot or its ancestors, not protected,
   and not younger than the child below them. A launch anchor becomes the root: a runner, a package manager (including
   npm's rewritten title and Corepack), a watcher (supervisord is not one), a program whose executable or script operand
   lies inside the listener's project, or a script-file shell whose script lies in the project. Non-interactive
   `sh -c` shells are climbed through but only included below a real anchor, so `claude → zsh -c → python` stops at
   the listener and never takes the agent's shell. The working directory alone is never proof: agents, editors and
   terminals all sit in the project folder.
3. Targets: the root and its descendants, breadth first, pruned at PortPilot, pid ≤ 1, protected processes and other
   users' processes, except the listener itself, which is always kept (another user's listener sets `requiresAdmin`).
   Ordered children first.
4. Warnings: auto-restart ("Will restart automatically (launchd: <label>) — use Stop & Disable Auto-Start"), exposed to
   the network, other listeners in the plan ("Also stops: …") and the administrator password prompt.

### Control/ProcessKiller.swift

```swift
final class ProcessKiller {
    init(pollInterval: TimeInterval = 0.1, killGracePeriod: TimeInterval = 2, ownPID: Int32 = getpid())
    func stop(_ plan: KillPlan, mode: StopMode, timeout: TimeInterval, allowAdmin: Bool,
              escalate: Bool = true) async -> StopResult
}
```

- Every signal is preceded by an identity check (`SysProc.basic(pid:)?.startTime`), so a recycled PID is never
  signalled. pid ≤ 1 and PortPilot are refused.
- Manager daemons (PM2 God Daemon, Docker backends) are refused even if a plan lists them, and so is any process group
  that contains one.
- Graceful: SIGTERM to each target, children first (plus SIGCONT when suspended), and to the root's process group only
  when the root leads its own group, PortPilot is not in it and every member is a planned target or unprotected; poll
  every 100 ms up to `timeout`; SIGKILL survivors; wait up to 2 s more. With `escalate: false` SIGKILL is never sent and
  survivors are reported ("Still running — use Force Kill").
- Force: SIGKILL immediately, then wait up to 2 s.
- EPERM: with `requiresAdmin` and `allowAdmin`, denied targets are signalled through `Shell.runAsAdmin` with a
  start-time guard in the shell command; otherwise they are failures.
- Runs detached from the caller's actor.


### Control/UpdateChecker.swift

### Control/AppMover.swift

"Move PortPilot to Applications" (offered by the welcome window when `InstallLocation.needsMove`: not a developer build
and not in /Applications or ~/Applications). `AppMover.install(from:)` stages a copy on the destination volume, strips
`com.apple.quarantine` from that copy only, refuses to touch a different app named PortPilot.app, opens a same-or-newer

this process has exited.

"New port opened: :5173 — my-app (Vite)". The first call records a baseline (no burst at launch); afterwards a port is

## UI contract

- `PortPilotApp`: `MenuBarExtra { PanelView(store:) } label: { MenuBarLabel(store:) }` with `.menuBarExtraStyle(.window)`;
  `LSUIElement` = YES (no Dock icon). `init` runs the headless modes, then changes the working directory to "/" (a
  launch folder inside Downloads, Documents or Desktop would otherwise make macOS ask for folder access again), then
  the single-instance check, and only then creates the store. Polling, update checks, folder-access tracking and the
  first-launch welcome window start from the menu bar label, so the count is live before the panel is first opened.
- Panel: 440 pt wide; the list scrolls and is at most 490 pt tall (≈ 620 pt panel). Native look: materials, SF Symbols,
  system fonts, light and dark mode. Everything happens inside the panel: sheets, alerts and separate windows would
  close the MenuBarExtra, so Settings replaces the list in place and confirmations are inline (`ConfirmButton`).
  While the panel is hidden, its body is an empty frame of the same height.
- Header: app glyph (a button that opens About; an accent dot while an update is available), "PortPilot", "Updated 2s
  ago", a summary of projects + background services ("7 ports · 4 projects · 1.2 GB · 6% CPU"), Refresh (spins only
  while a scan is visibly slow) and Settings. Shortcuts: ⌘R, ⌘F, ⌘, and ⌘Q. About and Settings replace the list in
  place; Esc or Done goes back, and the gear goes from About to Settings (`PanelPages`).
- `PanelNotices`: calm cards at the top of the list (not banners): "PortPilot 1.1.0 is available" (Download, Release
  Notes, Skip This Version) and, while a scan waits on a macOS folder-access prompt, "Waiting for access to Downloads.
  Click Allow in the macOS prompt so PortPilot can name your projects."
- Search matches every word against ports, titles, paths, commands, PIDs, frameworks, managers, origins and launchd
  labels; it also finds apps and system processes while they are hidden.
- Sections: Projects, Background Services, Apps, System (Apps and System only when enabled in Settings), each with a
  count and collapsible. Then "Still running · no open port" (`StillRunningView`), Recently Stopped and Startup Items

- `StillRunningView`: one row per tool whose ports closed while some of its processes kept running: its former ports
  struck through, the process labels, "closed 4m ago", CPU and memory, Stop (⌥-click force-kills) and a context menu.
- `GroupRow`: chevron, icon, title + subtitle, at most 3 port chips (4+ show 2 chips and "+N"; a chip opens

  actions.

- `StartupItemsView`: each non-Apple LaunchAgent with a status dot and line ("Running · PID 712", "Keeps failing · exit 78",
  "Loaded · not running", "Disabled"), KeepAlive marker, command, ports, an on/off switch (`setStartupItem`) and Start

## Safety rules (summary)

- Never signal pid ≤ 1, PortPilot or its ancestors, boundary or protected processes, the PM2 God Daemon, Docker
  backends, or another user's process unless it is the listener itself (then only after an administrator prompt).
- Re-verify every PID's start time immediately before signalling it.
- launchd: never edit or delete another job's plist (PortPilot only writes and removes its own LaunchAgent); write a
  `launchctl disable` only where Startup Items can undo it.
- pm2: never run a command without a running daemon; never run `pm2 save`; edit dump.pm2 only for the app being
  removed, keeping a `.bak`.
- Docker: only `docker stop` and `docker update --restart=no`, never a signal to the Docker process.
- Apps and macOS services: a plain Stop never sends SIGKILL; GUI apps are asked to quit and never force-quit.
- Network: the daily GitHub release check is the only request (it can be turned off); nothing is downloaded or
  installed automatically.
- Stopped commands, with their environment, stay in memory only.
- No subprocess, syscall-heavy work or signal on the main thread.

## Build, signing and tests

- `scripts/build.sh [--test]` generates the project with XcodeGen, optionally runs the tests, and builds the Release app
  into `dist/PortPilot.app`. `scripts/install.sh` installs the app into ~/Applications and registers its LaunchAgent;
  `scripts/uninstall.sh` removes both. `scripts/release.sh` builds a universal app, signs it with a Developer ID
  identity (hardened runtime, secure timestamp), notarizes and staples it, and builds the signed, notarized DMG.
- Local builds sign with an Apple Development identity when the keychain has one, else ad hoc
  (`PORTPILOT_ADHOC=1` forces ad hoc). A stable signature matters: macOS ties privacy permissions such as folder access
  to it, and an ad-hoc signature changes with every build, so the permission prompts would come back each time.
- Tests are pure-logic unit tests plus layout tests that render real views with synthetic data
  (`UIFixtures`, `PreviewData`). `PORTPILOT_PERF=1` enables the live-system benchmarks; `PORTPILOT_UI_SNAPSHOT_DIR`
  keeps the rendered PNGs. Tests that exercise signals or launchd only touch processes and jobs they create themselves.
